A. Folder Scan Summary
-----------------------
- Backend/Chat: A Python (FastAPI) application providing AI, voice, image scanning (ML), offline sync, sensor data analysis, and geographic processing. Connected to PostgreSQL, Redis, Pinecone, and Google Earth Engine.
- Backend/server: A Node.js (Express & TypeScript) application providing authentication (OTP), governance endpoints (land, fields, crops), chat history management, and Twilio/ElevenLabs voice agent integration (via WebSockets). Uses Prisma ORM and PostgreSQL.

C. Startup & Execution Flow
-----------------------
- Backend/Chat:
  1. Entry point: `app/main.py`
  2. `startup_event` triggers async connections (`init_db` for Postgres, `init_redis` for Redis) and loads ML models (crop disease detection).
  3. Registers middleware (`CORSMiddleware`).
  4. Includes endpoint routers with prefixes.
  5. Listens and processes REST & WS events.
- Backend/server:
  1. Entry point: `src/index.ts` -> `app.ts`
  2. Configures `express`, `cors`, `cookieParser`, `express-rate-limit`.
  3. Registers `routes` under `/api` and `voiceAgentRoutes` under `/api/voice-agent`.
  4. Wraps express app in standard HTTP `createServer(app)`.
  5. Sets up WebSocket Server on the HTTP Server path `/media-stream` for Twilio Voice stream.
  6. Listen on port 5000.

E. CI/CD Checklist
-----------------------
- Backend/Chat:
  - Start commands: `uvicorn app.main:app --host 0.0.0.0 --port 8001`
  - Build commands: Containerized via Dockerfile (`FROM python:3.11-slim`).
  - System Dependencies: Requires `build-essential`, `libpq-dev`, `libsndfile1`.
- Backend/server:
  - Dev command: `npm run dev` (`ts-node-dev --respawn --transpile-only src/index.ts`)
  - Build command: `npm run build` (`npx prisma generate && tsc`)
  - Start command: `npm run start` (`node dist/index.js`)
  - DB command: `npm run reset-db` (`npx prisma migrate reset --force && rm -rf prisma/migrations && npx prisma migrate dev --name init`)
  - Containerized via Dockerfile (`FROM node:20-alpine`, exposes 5000).

F. Risks & Missing Pieces
-----------------------
- Storage/State issues: In `Backend/server` (e.g. `sms.ts`, `addressSms.ts`, `networkFallback.ts`), the chat memory/fallback queues are stored in in-memory Maps (`sessions`, `pendingAddressRequests`, `pendingFallbackCalls`). This breaks completely in multi-instance (load balanced) environments.
- Hardcoded URLs: Some `allowed_origins` config in `.env` includes local addresses. Hardcoded `OLLAMA_URL` defaults.
- Testing Endpoints Exposed: `/api/test/protected` and `/api/test/admin` are included in production routes.
- Fragility in WebSocket stream: Unhandled rejections are ignored in `Backend/server` index.ts which might lead to zombies.
- CORS Issues: The Python backend has broad CORS access `allow_origins=[*]`, and Node.js has `origin: true` (reflecting origin).
- Tight coupling to specific hardcoded ML models (e.g., ai4bharat models, Gemini-2.5) that may need adjustments or might fail if weights are large/unavailable.
- High memory usage on startup in Python side as ML model weights load. Server boot might exceed standard timeouts in environments like Railway.
